# 千问服务管理：环境、按钮、休眠与唤醒

[返回使用手册](../README.md)

## 先确认这项功能是否适合你

STT 可以在悬浮窗中管理**另行配置好的本地千问服务**，不包含聊天窗口或模型安装器。

| 已经有什么 | 可以做什么 |
|---|---|
| 只下载 STT，没有模型环境 | 正常使用统计、大小写切换、时间流和倒计时；千问显示未配置 |
| 只有 Strata 或任意 OpenAI 兼容接口 | 不保证能管理，需要下述工具包与控制接口兼容 |
| 兼容工具包、Strata、模型及服务配置完整 | 可查询、启动、加载、休眠、强退和自动闲置管理 |

本发布包只提供 STT 和 `qwen_service.py` 适配器。**不包含 `qwen-collaboration` 工具包本体、模型权重、GPU 运行库或一键安装脚本**，也没有为其他电脑自动配置网络/防火墙。没有这些依赖时，不要只靠修改 STT 的 `config.txt` 期待模型启动。

## STT 怎样发现管理工具

按顺序查找当前用户的：

```text
~/.agents/skills/qwen-collaboration/scripts/manager.py
~/.agents/skills/qwen-collaboration/scripts/lifecycle.py

# 上面不可用时再找：
~/.codex/skills/qwen-collaboration/scripts/manager.py
~/.codex/skills/qwen-collaboration/scripts/lifecycle.py
```

这是兼容接口的发现位置，不表示本仓库会创建上述工具包。工具包还需拥有有效的服务配置、状态文件、运行目录和互斥能力；脚本同名不代表接口一定兼容。

外部服务配置至少需要明确本机回环 `base_url`、模型 ID、启动解释器、工作目录和命令参数。自动闲置管理要求 `lifecycle.owner = "stt"` 且外部 `lifecycle.enabled = false`，避免另一套闲置管理同时控制模型。

这些属于工具包配置，**不写进 STT 的 `config.txt`**。后者只有 `qwen_idle_timeout_minutes` 控制闲置时间，不负责模型路径、GPU 分配或网络地址。

## 状态与按钮

| 显示 | 意味着什么 | 左按钮 |
|---|---|---|
| 千问检测中 / 准备中 | 正在读取状态或准备服务 | 暂不可用 |
| 千问未配置 | 缺少工具包/配置 | 暂不可用 |
| 千问已停止 | 接收服务未运行 | 启动服务 |
| 千问待唤醒 | 接收服务运行，模型未加载 | 启动服务 |
| 千问启动中 | 正在请求启动或加载 | 暂不可用 |
| 千问就绪 | 模型已加载，未检测到执行或排队任务 | 休眠服务 |
| 千问工作 | 正在执行或排队 | 普通操作禁用 |
| 千问休眠中 / 退出中 | 正在处理对应操作 | 暂不可用 |
| 千问异常 | 状态查询、身份或配置等异常 | 可尝试启动/重查，先看悬停说明 |

常规后台查询约每 3 秒一次，不发模型生成请求。鼠标移到状态或按钮上可以查看细节和上次操作结果。

### 启动服务

- 服务已停止：启动接收服务，显式点击该按钮还会请求模型加载。
- 服务在、模型卸载：请求重新加载模型。
- 已就绪：不会为了“启动”再创建第二份已识别的服务。

STT 自身启动时调用的是**后台准备接收服务**，与手动点击的“启动服务”不同：已有已卸载模型保持待唤醒，不无故加载。若外部服务使用 `--lazy`，服务启动时不加载模型。

### 休眠服务

卸载模型，保留 HTTP 接收服务。成功后通常变为“千问待唤醒”。内存/显存释放量由引擎决定，不能承诺归零；接收进程本身仍需要资源。

普通休眠与自动休眠会检查执行/排队状态，不以打断任务的方式抢占资源。

### 强制退出：两次点击确认

1. 第一次点击“强制退出”，按钮变为四字“确认退出”。
2. **5 秒内再次点击**，才向独立后台强退通道提交退出。
3. 超过 5 秒没有确认，恢复“强制退出”；再次点击重新进入确认。

确认后会终止已核实身份的服务和子进程，**正在生成、加载或排队的任务会中断**。不等待普通操作队列或模型请求锁；重复提交合并处理。STT 取消本次旧启动流程，避免旧操作完成后又把服务拉起。

权限不足、进程身份不匹配或端口仍占用时会提示未完成，不能把按钮点击等同于必定成功。其他客户端自己发起的新启动不在 STT 取消旧流程的范围内。

右键的“完全关闭千问”仍是保留的普通关闭入口，忙碌时禁用，不等同于可见的强制退出。

## 默认两小时闲置休眠

在 STT 的 `config.txt` 全局区设置：

```ini
qwen_idle_timeout_minutes = 120
```

保存后刷新。单位分钟，正整数；缺失或非法时使用 120，非法原因记日志。`0` 不代表永不休眠。

- 兼容服务把本地与局域网请求都计入活动。
- 当前有执行或排队任务，不自动休眠。
- 最后一个任务完成后重新计算闲置时间。
- STT 查询状态不重置闲置时间。
- “休眠服务”手动卸载与闲置到期卸载，都会保留接收服务。
- 关闭 STT 后它不再执行闲置管理，接收服务继续保留。

此规则依赖服务提供可信的活动时间与任务数。状态未知时程序不会把“查不到”当成“可以自动结束”。

## 提前一分钟提醒

模型就绪且剩余闲置时间在 60 秒以内时显示提醒，沿用小窗口样式，不主动抢走当前任务焦点。

默认按钮为 **“重置 2 小时”**；点击后重新获得完整闲置时长。比如设为 7 分钟，按钮显示“重置 7 分钟”。有新任务或模型已卸载时，状态更新后隐藏提醒。

提醒依赖后台轮询，不是硬实时倒计时。关闭提醒窗口不会重置闲置时间；若需要延期，请点击重置按钮。

## 局域网自动唤醒与免密范围

自动唤醒发生在**接收服务已经运行，但模型已卸载**时。远程客户端向兼容服务提交正常推理请求，服务负责加载模型再处理请求。

必须同时具备：电脑开机、未进入系统睡眠、服务仍监听正确网卡/地址、客户端网络可达、防火墙和允许网段匹配。**完全退出服务后，远程请求不能直接启动它；STT 不提供远程开机或系统唤醒功能。**

本机控制使用回环地址，例如 `http://127.0.0.1:8080/v1`；其他设备填写运行模型那台电脑的实际局域网地址。不要把 `127.0.0.1` 当成别的电脑的地址。

本发布的 `qwen_service.py` 适配器支持免 API Key 模式和网段过滤：允许范围内的推理访问无需填 key，管理接口只允许本机。外部工具包也要配置一致，旧服务若仍要求密钥，仅刷新 STT 配置不会消除它的认证。

开发者示例（路径、端口和网段必须换成自己的值）：

```powershell
python qwen_service.py --strata-server "C:/Tools/Strata/serve/server.py" --allow-subnet 192.168.1.0/24 --engine strata --config "C:/Tools/Strata/model.json" --host 0.0.0.0 --port 8080 --idle-unload 0 --lazy
```

这是接收层启动形式示例，不包含模型配置，也不是工具包安装命令。`--allow-subnet` 可以重复提供；未配置允许网段时只接受本机。Strata 配置自身也可能影响监听地址，需要与启动参数一起检查。

## 模型就绪为什么慢

“接收服务启动”“权重加载完成”“当前请求处理完成”是三个阶段。等待就绪可能包含从存储读取权重、锁定内存、填充 GPU 缓存及等待已有任务。

`--lazy` 决定**何时加载**，不会把显存固定限制在某个数值。显存/内存分配由模型、专家缓存、KV、视觉组件及引擎参数决定。STT 不修改这些模型参数，也不把全部模型强行塞进显存。

超时后服务可能仍在加载，先查状态和服务日志，不要反复提交同一生成任务。当前单次加载等待参数与后续轮询不是整个操作的严格统一总上限，不能把 300 秒解释为所有步骤必定在 300 秒内结束。
