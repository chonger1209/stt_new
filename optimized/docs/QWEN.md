# 千问管理：配置、状态、启停与休眠

[返回使用手册](../README.md) · [换机逐步教程](QWEN_SETUP.md) · [配置字段](CONFIGURATION.md)

## 依赖与安装

便携包附带 `配套资源/千问管理工具包`，包含 manager.py、lifecycle.py、qwen_service.py、service.json 和 state.json 模板。模型、兼容版本的 Strata、运行环境和 GPU 库需要另行安装；单独 EXE 不附工具包。不是通用 Ollama/LM Studio 管理器，不要求安装 Codex。

在 STT config 中填写 qwen_toolkit_path（工具包根目录）；留空依次查找 ~/.agents/skills/qwen-collaboration、~/.codex/skills/qwen-collaboration。详细安装、填写和测试步骤见换机教程。

## 配置与生效

- qwen_enabled=false 时不查询或控制服务，普通统计照常。
- qwen_prepare_service_on_start=true 时在 STT 启动后准备接收服务，不主动预加载模型。
- 连接地址、模型、解释器、工作目录、JSON 参数和启动总超时统一在 STT config 编辑。旧电脑只补缺失字段，已有值和注释优先保留。
- 路径/模型等服务参数刷新后暂存，现有进程继续按原共享配置管理。等任务结束并关闭原服务，再点击启动；校验成功后自动备份并写入工具包 service.json。
- 空值沿用工具包配置，初装空模板需填写完整。管理地址只支持本机回环 HTTP /v1。引擎显存、上下文等参数仍在已验证的引擎配置中设置。
- 不新增 API Key 要求；保留现有免密和网络范围策略，管理接口仍限制本机。

## 状态、颜色与速度

| 状态 | 含义 | 速度 |
|---|---|---|
| 千问未启用 | config 关闭了管理 | 0.0 T/s |
| 千问未配置 | 缺少工具包或完整配置 | — T/s |
| 千问已停止 | 接收服务不在运行 | 0.0 T/s |
| 千问待唤醒 | 接收服务在，模型已卸载 | 0.0 T/s |
| 千问就绪（灰） | 已加载且未检测到任务 | 0.0 T/s |
| 千问预读（蓝） | 读取上下文 | 0.0 T/s |
| 千问生成（绿） | 正在输出 token | 如 57.6 T/s |
| 千问排队（黄） | 请求等待处理 | 0.0 T/s |
| 千问异常（红） | 服务/身份/配置/查询异常 | — T/s |

并行时生成优先，队列数量和预读进度在悬停提示中。速度来自 /metrics 最近时间窗口的合计输出速率，不叠加槽位历史平均值。非生成阶段清零，缺失指标显示未知，不保留上次速度。不显示预读速度。

工作约每秒、空闲约每三秒后台串行查询；没有逐 token UI 推送。值不变时不重复绘制，状态请求不重置闲置时间。指标不可用时保留原有“千问工作”及忙碌保护。只提取白名单指标，不存储提示词或回答。

状态 MiSans12磅常规、速度 MiSans11磅常规，缺失回退等线；按钮等线9磅常规。速度独立高对比颜色，状态颜色按背景调整可读性，不改变用户背景色。

## 按钮

- 启动服务：必要时启动接收服务，然后请求加载模型。使用统一启动等待预算；超时后服务端可能仍在加载，不等同于进程退出。
- 休眠服务：卸载模型，保留接收服务。自动/普通休眠保护执行与排队任务；显存内存释放量由引擎决定。
- 强制退出：第一次进入“确认退出”，5秒内第二次点击才通过独立通道终止已核实身份的服务和子进程，任务会中断。超时恢复，重复确认合并，不等待普通操作队列。

强退取消旧启动流程，权限不足或无法核验身份时报告失败，不假报已停止。其他客户端自己发起的新启动不属于 STT 的旧操作取消范围。右键普通关闭忙碌时禁用。

## 两小时闲置与远程请求

qwen_idle_timeout_minutes 默认120，提前1分钟提醒；点击重置重新计完整时长。任务结束后重新计算；损坏或未知活动信息不作为休眠许可。STT 退出后不继续管理闲置，也不自动退出模型服务。

局域网请求可唤醒已卸载模型，前提是电脑开机、未系统睡眠、接收服务仍运行且网络允许。完全退出服务后远程请求无法直接启动进程。STT 当前只管理本机服务，不支持把管理地址改成远程IP。发布包不会自动开放防火墙。

真实推理、其他电脑端到端访问及长期运行耐久不属于本次模拟测试的通过项。
