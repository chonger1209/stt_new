# STT 2026.10.22.2 · 千问增强版使用手册

STT 是 Windows 桌面悬浮工具，把 **Caps Lock 状态、按软件自动切换大小写、前台应用计时、彩色时间流和番茄倒计时** 放在一个小窗口里。配置兼容环境后，还能管理本地千问模型服务。

本手册对应 `v2026.10.22.2` 优化版。[基础版](https://github.com/chonger1209/stt_new/releases/tag/stt_new) 仍可下载；旧版的功能与计时实现不以本手册为准。

## 千问状态与生成速度

状态、速度、按钮按三行排列，与左侧倒计时对齐。状态字体 MiSans 12 磅常规，缺失时等线；速度为 MiSans 11 磅常规，按钮为等线 9 磅常规。

| 状态 | 颜色 | 速度 |
|---|---|---|
| 千问就绪 | 灰 | `0.0 T/s` |
| 千问预读 | 蓝 | `0.0 T/s` |
| 千问生成 | 绿 | 如 `57.6 T/s` |
| 千问排队 | 黄 | `0.0 T/s` |
| 千问异常 | 红 | `— T/s` |

生成速度取服务 `/metrics` 最近时间窗口的合计输出速率，保留一位小数；不显示预读速度，不叠加各槽位的历史平均值。并行时优先显示生成，队列数量在悬停提示中。预读、排队、就绪及结束后清零，避免保留上次速度。生成指标缺失显示 `— T/s`。

工作约每秒查询一次，空闲约每三秒查询一次；后台串行执行，无逐 token UI 更新，值不变时不重复绘制。指标接口不兼容/超时会退回“千问工作”和未知速度，保留控制及忙碌保护。只读取白名单指标，不保存请求文本或回答。配色依据原背景调整文字对比度，不改变用户背景设置。

## 本修订的主要变化

- 千问设置集中在 config，附管理工具包模板与详细换机教程；非法路径、地址和参数明确提示字段。
- 状态 MiSans 12 磅、速度 MiSans 11 磅，均为常规体；按钮等线9磅，三行居中。背景配色保持用户设置。
- 统计排除系统睡眠并抵御校时；回执异常按批次身份恢复，避免重试已提交记录。
- 启动等待使用统一总预算；数据库持续故障一分钟提示；日志轮转；改善低权限进程识别、配置刷新和多屏定位。

| `stt_new-2026.10.22.2-windows-x64.exe` | 仅程序，首次运行自动生成配置和数据文件 |
| `STT-2026.10.22.2-source.zip` | 新版源码和文档，运行需 Python 及依赖 |
| `STT-2026.10.22.2-SHA256SUMS.txt` | 下载完整性校验 |

便携程序面向 Windows x64，不需要安装 Python。未提供 macOS/Linux 可执行程序。

1. 把 ZIP 完整解压到可写目录。
2. 双击 `stt_new.exe`。程序读取或生成 `config.txt`，后台创建/打开数据库和日志目录。

## 窗口与菜单

- 背景色随 Caps Lock 状态变化，颜色可配置。
- 移入窗口或靠近上沿显示标题栏，离开后延迟隐藏。
- 在可拖动的空白区域或标题栏拖动。按钮操作不会同时触发窗口拖动。
- 正常退出保存横纵坐标；多显示器允许负坐标。
- 窗口可调整尺寸，字号、行高和色块不会随窗口尺寸自动等比例缩放。

| 操作 | 结果 |
|---|---|
| `📊` / 右键“统计” | 展开或收起当天统计，展开后通常约 30 秒自动收起 |
| `⚙` / 右键“设置” | 使用系统关联编辑器打开 `config.txt` |
| `⟳` / 右键“刷新” | 重读设置，不清空统计 |
| `×` / 右键“关闭” / `Esc` | 正常退出 STT，先保存待写记录 |
| 右键“启动/加载千问” | 请求启动服务或加载模型，需兼容环境 |
| 右键“完全关闭千问” | 普通关闭入口，忙碌时禁用，与可见的强退按钮不同 |
| 右键“刷新千问状态” | 主动查询状态，不发送生成请求 |

关闭 STT 是退出程序，当前没有隐藏到系统托盘功能。悬停时间流格子或千问控件可查看应用名称、状态与上次操作说明。

## Caps Lock 与自动大小写

窗口显示 `Caps Lock ON / OFF`。默认 ON 红色、OFF 绿色。

每约 200 毫秒检查一次前台窗口；**前台窗口切换时**，根据应用显示名称或窗口标题匹配软件关键词，忽略大小写：

```ini
software_list = CAXA,CAD,SOLIDWORKS
```

命中任意关键词时开启 Caps Lock，未命中时关闭。列表留空表示切换到任何软件时都关闭 Caps Lock，**不代表停用自动切换**。

同一窗口中可以手动切换 Caps Lock；程序不会每 200 毫秒强制改回，下一次检测到前台窗口切换时才重新判断。仅窗口标题改变但窗口句柄未变，不一定触发重新匹配。

此功能管理键盘大写锁定状态，不是输入法中英文切换，也不会转换已经输入的文字。识别受进程权限影响时可能回退窗口标题。

## 应用时长统计

### 统计口径

记录**前台窗口对应应用的经过时长**。切换应用时结算上一段，界面合并已保存区间、待写区间和当前尾段。

只统计 STT 实际运行期间。后台运行但未处于前台的软件不会单独累计。当前没有键鼠闲置检测，不能自动区分“人在使用”和“人离开但前台窗口没变”。本修订排除系统休眠并抵御校时跳变；不把系统休眠时间记作前台使用时长。

### 统计面板

点 `📊` 展开当天统计。按累计时长从高到低排序，最多前 50 项，可滚动查看。

- 数字是应用当天累计时长，超过一小时显示为 `小时:分钟:秒`。
- 柱长相对最大项缩放，不代表 CPU、内存或使用百分比。
- 默认约每秒刷新，配置可以降低频率。
- 当前界面只展示当天，没有历史日期选择、CSV 导出或云同步。

### 名称、隐藏与合并

未写进配置的程序也正常记录和显示；进程规则用于改名/隐藏，不是白名单：

```ini
[LockApp.exe]
display_name = Lock Screen
show_in_screen_time = false
show_in_time_stream = true
```

这里表示在柱状统计中隐藏锁屏程序、在时间流中保留。`false` 只隐藏对应视图，不停止记录、不删除数据库历史。

不同程序使用相同 `display_name` 会合并统计。修改显示名称主要影响后续记录，不会批量重写历史数据库中的旧名称。建议使用不同名称；完整规则见 [配置手册](docs/CONFIGURATION.md)。

## 彩色时间流

底部格子按当天应用区间顺序排列。**每格代表指定的累计有效时长**，默认 30 秒。改成一分钟一格：

```ini
grid_second_per_block = 60
```

该设置也影响定时采样/时间流更新间隔，界面不是必须每秒补画。

### 格子如何产生

1. 不同应用的短片段共同累计。
2. 满一格才绘制，余数继续保留。
3. 颜色归这一格累计结束时的应用。
4. 切换应用、采样、刷盘和重启不会单独额外生成格子。

| 60 秒/格的例子 | 结果 |
|---|---|
| A 50 秒 + B 10 秒 | 1 格，颜色归 B |
| A 50 秒 + B 9 秒 | 暂时 0 格，保留 59 秒余数 |
| 1 小时内每 5 秒切一次应用 | 有效可见时长恰为 1 小时时，共 60 格 |

设为 `show_in_time_stream = false` 的应用区间不参与可见格子的累计，所以可见格数可能少于墙上时钟经过时间除以每格秒数。

悬停格子查看对应应用名。颜色来自内置调色板，目前没有永久固定某程序颜色的配置，重启后颜色不保证一致。

格子够多时换行，Canvas 请求高度会增加。但受窗口和屏幕空间限制，**当前不保证无限自动增高、完整滚动或永不裁切**。空间不足可调整窗口尺寸或提高每格秒数。

## 番茄倒计时

默认 `25:00`，时长由 `timer_duration_minutes` 控制。

| 按钮 | 行为 |
|---|---|
| `▶` | 开始；暂停后继续剩余时间 |
| `⏸` | 暂停并保留剩余时长 |
| `⏹` | 停止并重置到当前配置时长 |

倒计时采用单调时钟，短暂界面延迟不会让时间按“回调次数”越走越慢。完成后停在 `00:00`，可以重新开始。

修改时长后刷新：尚未开始则更新；运行或暂停中保留剩余时间，重置后使用新时长。当前没有自动休息周期、连续番茄循环、提示音或完成通知弹窗。

## 可选千问管理

便携包包含兼容 Strata 的管理工具包模板（manager.py、lifecycle.py、服务适配器和空配置），不包含模型、Strata、GPU 环境或一键安装器。单独 EXE 不附工具包；未配置时普通统计仍可使用。

从 [换机配置教程](docs/QWEN_SETUP.md) 开始：先让模型在兼容环境中单独运行，再在 STT 的 config 填写工具包路径、服务地址、模型 ID、Python、工作目录、JSON 参数及启动总超时。已有电脑从实际 service.json 补入缺失字段，不重置已有值；新电脑不能直接照搬旧路径。

刷新只暂存服务参数，不重启正在工作的服务。身份/路径改变时先等待任务结束并关闭原服务，再点“启动服务”；STT 验证后备份并同步共享 service.json。无需手改两份文件。GPU 和模型引擎参数仍由引擎配置管理。

| 状态/按钮 | 含义 |
|---|---|
| 千问未配置 | 缺少工具包或服务配置；普通 STT 仍可使用 |
| 千问已停止 | 接收服务未运行 |
| 千问待唤醒 | 接收服务运行，模型未加载 |
| 千问就绪 | 模型已加载，当前没有检测到执行/排队任务 |
| 千问工作 | 有任务执行或排队 |
| 启动服务 | 已停止时启动并加载；待唤醒时加载模型 |
| 休眠服务 | 卸载模型，保留接收服务；忙碌时不允许普通休眠 |
| 强制退出 → 确认退出 | 首次点击进入确认，5 秒内再点才强退服务及子进程，会中断任务 |

强退确认超时后恢复“强制退出”，重复确认会合并处理。加载、工作或普通操作期间仍可请求强退；权限不足或身份无法核验时会报告未完成，不假报已退出。

状态文字前使用小中点。状态字体优先 MiSans、缺失回退等线，12 磅常规字重；速度为 MiSans 11 磅常规字重，按钮为等线 9 磅常规字重。

闲置休眠默认 **120 分钟**，提前 **1 分钟**提醒，点击“重置 2 小时”重计完整时长。修改分钟数后，计时与重置文案同步改变。本地、局域网任务均由兼容服务计入活动；状态查询不重置计时。

STT 启动时后台准备接收服务，**不会强制把已卸载模型预加载**；点击“启动服务”或后续请求才可能加载。退出 STT 只停止其闲置管理，不自动关闭千问服务。

局域网请求自动唤醒要求电脑开机、未进入系统睡眠、服务仍监听且网络允许。完全退出服务后，远程请求无法直接唤醒。加载耗时和内存/显存释放量取决于模型与引擎。

环境、状态、按钮和故障排查见 [千问管理说明](docs/QWEN.md)。

## 配置与数据文件

`config.txt` 使用 UTF-8，保存后点 `⟳`。**全局配置必须放在第一个 `[进程名]` 前面。**

```text
STT/
├─ stt_new.exe
├─ screen_time_tracker_new.ico
├─ config.txt
├─ screen_time_history.db
├─ time_stream_history.db
├─ logs/
├─ 使用说明.md                  # 便携包提供
├─ docs/                       # 便携包提供详细手册
└─ 配套资源/千问管理工具包/    # 含适配器与共享配置模板
```

| 文件 | 作用 |
|---|---|
| `config.txt` | 实际用户设置，不存在时生成 |
| `config.default.txt` | 源码默认模板示例，不作为实际用户配置读取 |
| `screen_time_history.db` | 应用使用时长历史 |
| `time_stream_history.db` | 应用时间区间与区间日志 |
| `logs/stt.log` | 当前运行日志，2 MiB 轮转，保留5份备份；旧日期日志保留 |
| `config.txt.before_config_upgrade.bak` | 首次升级旧格式配置时可能生成的备份 |
| `配套资源/千问管理工具包/` | manager/lifecycle、接收适配器和空配置模板；不包含模型服务 |

初始化或写入失败时，数据库可能暂时尚未创建/更新，请查看日志与提示。不要在运行中删除数据库或更换数据目录。

## 后台保存与退出

应用切换、采样先结算区间；通常每约 60 秒请求保存，待写区间达到阈值时也请求保存。数据库由单独线程独占连接。

- 一个事务同时写两份数据库；成功回执到达后才从待写列表移除这一批。
- 忙、被锁或写入失败时保留原批次并后台重试，界面不等待 SQLite 锁超时。
- 正常关闭先补记最后一段，等待保存和数据库关闭；保存失败时保持运行并提示，稍后再退出。
- 强制结束 STT、断电或系统崩溃仍可能丢失尚未落盘的尾段；后台队列不是断电恢复日志。

单实例按**数据目录**生效：同目录第二次启动新版会提示已有实例，不启动第二套采样。不同目录可以有不同数据集。旧版没有此保护，仍需避免与新版同时运行同目录数据。

## 升级迁移与回退

### 保留设置和历史记录升级

1. 从旧 STT 正常退出，等待保存完成。
2. 备份整个目录，至少保留 `config.txt` 和两份 `.db`。
3. 替换新版 EXE、按需放入图标，保留原配置和数据库。
4. 启动后核对当天统计、配色、窗口位置与软件显示规则。

不要用 ZIP 内的默认配置覆盖个人配置。旧配置缺少新字段时会补齐；旧格式升级可能生成 `.bak`，已有进程显示选择会保留。

### 换目录或换电脑

退出后复制 EXE、图标、`config.txt` 和两份数据库。统计数据不依赖原工作目录。千问属于独立环境，可能引用本机路径，需要在新电脑重新配置，不能只搬 EXE 就获得模型服务。

### 回退

退出新版并备份当前最新数据，再换回旧 EXE。不要用升级前数据库覆盖新增记录。两版延续原数据库结构，但旧版对新增配置、计时和时间流的解释可能不同，建议先在副本核对。

## 当前能力边界

本版未提供键鼠闲置过滤、跨设备同步、历史日期浏览、数据导出、系统托盘、开机自启安装、自动更新或无限高度时间流。

使用时长由 Windows 清醒时间计量，排除系统休眠，不受系统校时跳变影响；区间日期仍按本地日历时间归档。番茄倒计时使用单调时钟。持续写入失败时待保存记录仍占内存，不能承诺内存绝对恒定。新日志单文件约 2 MiB、保留 5 份轮转备份；已有日期日志不自动删除。数据库没有自动清理期限。

千问管理只面向实现了所需接口的兼容环境，不是通用 Ollama、LM Studio 或任意 OpenAI 兼容服务管理器。
